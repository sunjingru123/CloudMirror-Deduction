# 已知限制（KNOWN LIMITATIONS）

> 项目：云镜推演（CloudMirror Deduction）
> 对应代码版本：`fefaebd`
> 目的：如实说明当前能力边界，区分「已实现 / 未实现 / 后续计划」。

---

## 一、最重要的前提：这是虚拟推演平台

> **本平台只进行虚拟故障推演，不会实际操作任何云资源。**
>
> - 不执行真实的服务重启、流量切换（failover）、节点隔离。
> - 不连接真实的云平台、Kubernetes、负载均衡器或监控系统。
> - 所有「恢复时间」「资源成本」「影响节点数」「评分」均为**基于规则的模拟估算值**，
>   不是真实生产环境的测量数据。
> - 恢复策略是一份**建议**，用于在动手前评估影响范围与候选方案，不能替代运维决策与演练。

请勿将本平台的输出描述为「已完成的真实恢复」。

## 三、已知限制（L-01 ~ L-18）

> 「已实现」不代表「生产级」。以下为当前版本的明确边界。

### 3.1 虚拟推演性质

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| L-01 | 不操作真实云资源 | 平台只做推演，不执行任何真实变更操作 |
| L-02 | 不执行真实切流 | failover 只输出「建议切换到备用节点」，不会真实切换流量 |
| L-03 | 无真实环境校验 | 不校验真实容量、网络连通性、数据同步状态、配置一致性、健康探测结果 |

### 3.2 传播分析与模型

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| L-04 | 纯结构传播 | 传播范围仅由「依赖结构 + 激活故障源」决定；`fault_type` 与 `severity` 只作快照记录，**不改变**传播范围 |
| L-05 | 影响等级仅两级 | 只有 `direct`（距离 1）与 `indirect`（距离 ≥ 2），未细化到严重程度分级 |
| L-06 | 不建模冗余与多实例 | 不模拟负载均衡、多实例、副本；某个节点被判定受影响即计入，不考虑「仍有冗余实例可用」从而降低影响 |
| L-07 | 三个概念彼此独立 | 「节点原始状态」「激活故障事件」「算法计算的影响状态」相互独立：注入故障**不会**自动修改节点 `status`，算法结果也**不会**回写节点状态 |

### 3.3 恢复策略

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| L-08 | 评分为固定权重规则 | 权重与估算参数集中配置、固定不变，未经真实数据标定；评分是相对排序而非真实收益 |
| L-09 | 双活不支持切换 | `active_active`（双活）当前**不**生成主备切换方案，对应检查项「冗余模式是否支持切换」为 ✕ |
| L-10 | 手动备用与主备判定相同 | `manual_standby` 与 `active_standby` 的适用性判定完全一致，未区分自动化程度与人工介入成本 |
| L-17 | 隔离不等于恢复 | `isolate_node` 只阻断扩散，不恢复故障节点服务；若隔离会让用户入口失去全部可用依赖，则标记为高风险的「不适用」 |

### 3.4 数据与快照语义

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| **L-11** | **分析结果为快照** | `GET .../analysis/latest` 返回**最近一次存储的分析记录**，不会因故障恢复而自动失效或重算。恢复故障后需**重新执行分析**才会更新结果，页面在此之前仍显示旧分析的高亮。这是「快照语义」的设计取舍，不是自动实时状态 |
| L-12 | 一个节点最多属于一个冗余组 | 跨组复用（如某节点既是 A 组主节点又是 B 组备用）暂不支持，服务层会明确拒绝 |
| L-13 | 冗余关系不参与传播计算 | 冗余关系只服务恢复策略；故障传播只依据依赖边，二者语义独立 |

### 3.5 工程与部署

| 编号 | 限制 | 说明 |
| --- | --- | --- |
| L-14 | 无认证 / 单机存储 | 无用户认证与多租户；数据库为单机 SQLite，不适合多用户并发生产使用 |
| L-15 | 无实时推送 | 前端通过请求 - 响应获取数据，无 WebSocket / 服务端推送 |
| L-16 | 无前端自动化测试 | 前端仅有 `vue-tsc` 类型检查与生产构建，无 E2E 自动化测试，浏览器端功能需人工验收 |
| L-18 | 无真实健康探测 | 备用节点「可用」仅由当前模拟模型的规则判定，未做任何真实健康探测 |

## 五、表达规范（避免误导）

在文档、答辩与页面文案中，应保持以下表达：

- 说「模拟估算」「推演结果」「建议策略」，不说「已完成恢复」「真实恢复」。
- 说「备用节点候选」「建议切换」，不说「已切换流量」。
- 说「基于规则的加权评分」，不说「AI 模型预测」。
- 提到恢复时间 / 成本时，明确标注「模拟估算值，非真实测量」。
