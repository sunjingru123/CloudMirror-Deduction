## 2. 依赖方向约定（务必统一）

> **边 `A → B` 表示「A 依赖 B」**，即 `source_node_id = A`（依赖方）、`target_node_id = B`（被依赖方）。

- 前端 Vue Flow 中，箭头由 A 指向 B（指向被依赖方），与后端字段一一对应。
- 故障传播方向与依赖方向相反：依赖边 `A → B` ⇒ 传播路径 `B → A`，即 **B 故障时 A 可能受影响**。
- 约定在以下位置保持一致的注释与文档说明，避免「画布箭头方向」与「算法方向」不一致：
  - `backend/app/models/topology.py`
  - `backend/app/api/topologies.py`
  - `backend/app/services/topology_service.py`
  - `frontend/src/api/topology.ts`
  - `frontend/src/components/TopologyNode.vue`（底部 source / 顶部 target）

## 4. 数据库表结构

### 4.1 `topology`（拓扑）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, 自增 | 主键 |
| `name` | VARCHAR(128) | NOT NULL, UNIQUE, INDEX | 拓扑名称 |
| `description` | TEXT | NULL | 描述 |
| `created_at` | DATETIME | NOT NULL | 创建时间（UTC） |
| `updated_at` | DATETIME | NOT NULL | 更新时间（UTC） |

### 4.2 `topology_node`（节点）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, 自增 | 主键 |
| `topology_id` | INTEGER | FK → `topology.id` ON DELETE CASCADE, INDEX | 所属拓扑 |
| `name` | VARCHAR(128) | NOT NULL | 节点名称 |
| `type` | VARCHAR(32) | NOT NULL | 节点类型（枚举校验） |
| `description` | TEXT | NULL | 描述 |
| `status` | VARCHAR(16) | NOT NULL, 默认 `healthy` | 节点状态 |
| `position_x` | FLOAT | NOT NULL, 默认 0 | 画布 X 坐标 |
| `position_y` | FLOAT | NOT NULL, 默认 0 | 画布 Y 坐标 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |
| `updated_at` | DATETIME | NOT NULL | 更新时间 |

### 4.3 `topology_edge`（依赖关系）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, 自增 | 主键 |
| `topology_id` | INTEGER | FK → `topology.id` ON DELETE CASCADE, INDEX | 所属拓扑 |
| `source_node_id` | INTEGER | FK → `topology_node.id`, INDEX | 依赖方（source） |
| `target_node_id` | INTEGER | FK → `topology_node.id`, INDEX | 被依赖方（target） |
| `description` | TEXT | NULL | 依赖说明 |
| `created_at` | DATETIME | NOT NULL | 创建时间 |

**约束**：

- `UNIQUE (topology_id, source_node_id, target_node_id)`：防止重复边。
- `CHECK (source_node_id <> target_node_id)`：防止节点自依赖。
- 拓扑删除时级联删除其节点与依赖；节点删除时级联 / 显式删除相关依赖。
- 允许存在环路（A → B → C → A），传播算法需自行处理环路。

**SQLite 外键**：连接建立时通过 `PRAGMA foreign_keys=ON` 开启外键约束，
使 `ON DELETE CASCADE` 生效（见 `backend/app/core/database.py`）。

**幂等初始化**：使用 `Base.metadata.create_all()`，重复启动不会清空或重建数据。

## 5. API 清单

基础前缀：`/api`。错误响应统一为 `{"detail": "中文说明"}`。

| 方法 | 路径 | 成功码 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 200 | 健康检查 |
| POST | `/api/topologies` | 201 | 创建拓扑 |
| GET | `/api/topologies` | 200 | 拓扑列表（含节点数 / 依赖数） |
| GET | `/api/topologies/{id}` | 200 | 拓扑详情（含 nodes、edges） |
| PUT | `/api/topologies/{id}` | 200 | 更新拓扑名称 / 描述 |
| DELETE | `/api/topologies/{id}` | 204 | 删除拓扑（级联） |
| POST | `/api/topologies/{id}/nodes` | 201 | 添加节点 |
| PUT | `/api/topologies/{id}/nodes/{node_id}` | 200 | 编辑节点 |
| DELETE | `/api/topologies/{id}/nodes/{node_id}` | 204 | 删除节点（级联相关依赖） |
| POST | `/api/topologies/{id}/edges` | 201 | 添加依赖关系（source → target） |
| DELETE | `/api/topologies/{id}/edges/{edge_id}` | 204 | 删除依赖关系 |

### 错误码约定

| 场景 | 状态码 |
| --- | --- |
| 拓扑 / 节点 / 依赖不存在 | 404 |
| 拓扑名称重复、重复边 | 409 |
| 节点自依赖 | 400 |
| 请求体字段非法（如未知节点类型） | 422（FastAPI / Pydantic） |

服务层通过 `app/services/exceptions.py` 抛出业务异常，由 `app/main.py` 的异常处理器统一转换。

## 6. 前端实际操作流程

页面：`/topology`（列表）与 `/topology/:id`（编辑器）。

1. **进入列表**：`GET /api/topologies` 加载拓扑；失败时页面顶部显示错误并提供「刷新」。
2. **新建拓扑**：点击「新建拓扑」→ 填写名称 / 描述 → `POST /api/topologies` → 自动进入编辑器。
3. **进入编辑器**：`GET /api/topologies/{id}` 读取节点与边，并在 Vue Flow 中真实渲染。
4. **添加节点**：右侧「添加节点」中点击某类型 → `POST .../nodes`（同时写入初始坐标）。
5. **拖动节点**：松手时 `PUT .../nodes/{id}` 自动保存坐标（提示「节点位置已保存」）。
6. **创建依赖**：从节点**底部**圆点拖到另一节点**顶部**圆点 → `POST .../edges`；
   自依赖或重复边会被后端拒绝并弹出提示，画布不会留下非法连线。
7. **选中节点**：点击节点 → 右侧面板编辑名称 / 类型 / 状态 / 描述 → 「保存节点」→ `PUT .../nodes/{id}`。
8. **删除节点**：选中后点「删除节点」→ 二次确认 → `DELETE .../nodes/{id}`，
   相关依赖同步从前端移除。
9. **删除依赖**：点击连线 → 右侧面板点「删除依赖关系」→ `DELETE .../edges/{id}`。
10. **重命名拓扑**：顶部「重命名」→ `PUT /api/topologies/{id}`。
11. **保存布局**：顶部「保存布局」批量提交所有位置发生变化的节点坐标。

所有增删改均调用真实后端 API，不使用本地假数据；未保存的非法操作不会污染服务端状态。

## 7. 本地启动与测试

### 启动

```bash
# 后端（终端 1）
cd backend
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
# → http://127.0.0.1:8000/api/health   http://127.0.0.1:8000/docs

# 前端（终端 2）
cd frontend
npm install
npm run dev
# → http://127.0.0.1:5173
```

### 测试与构建

```bash
cd backend && pytest          # 25 个测试
cd frontend && npm run build  # vue-tsc 类型检查 + 生产构建
```
