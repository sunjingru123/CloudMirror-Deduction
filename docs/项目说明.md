# 项目说明

## 1. 项目概况

- **项目名称**：云镜推演
- **英文名称**：CloudMirror Deduction
- **项目定位**：面向云原生业务系统的故障传播分析与恢复策略优化平台
- **项目地址**：<https://github.com/sunjingru123/CloudMirror-Deduction>
- **当前阶段**：第一阶段 · 工程初始化（已完成前后端基础联调）

> 本文档如实记录当前已完成的工程内容。标注为「规划中」的功能尚未实现，
> 请勿视为已交付能力。

## 2. 技术选型

| 层次 | 技术 |
| --- | --- |
| 后端 | Python 3.11+、FastAPI、Pydantic、SQLAlchemy、SQLite |
| 前端 | Vue 3、Vite、TypeScript、Element Plus、Vue Flow、Axios |
| 测试 | pytest |
| 包管理 | pip / npm |

## 3. 已完成内容

### 3.1 后端（backend/）

- 标准 FastAPI 工程结构：`app/main.py`、`core/`、`api/`、`models/`、`schemas/`、`services/`。
- 应用入口 `app/main.py`：配置 CORS、注册路由、启动时初始化数据库。
- 健康检查接口 `GET /api/health`，返回 `status`、`project_name`、`project_name_en`、`version`。
- 根路径 `GET /` 返回项目信息与文档入口（不在接口文档中展示）。
- CORS 允许本地 Vue 开发服务器（`5173` / `3000`）访问，可通过 `CORS_ORIGINS` 配置。
- SQLite + SQLAlchemy 基础初始化：`engine`、`SessionLocal`、声明式 `Base`、`get_db` 依赖、`init_db`。
  当前**尚未定义任何业务表**。
- `.env.example` 提供环境变量示例（不含真实密钥）。
- 基础测试 `tests/test_health.py`：验证健康检查返回、响应类型与根路径。

### 3.2 前端（frontend/）

- Vue 3 + Vite + TypeScript 工程。
- Vue Router 四个路由：`/`（Dashboard）、`/topology`、`/fault-simulation`、`/history`。
- Element Plus 与图标全局注册，全局浅色科技风样式。
- Vue Flow 已接入，拓扑页为画布占位示意（**未接入后端数据**）。
- Axios 实例封装：统一 `baseURL`（`VITE_API_BASE_URL`，默认 `http://127.0.0.1:8000`）与超时。
- 首页 Dashboard：展示项目名称、简介与**真实后端连接状态**；
  挂载后自动请求 `/api/health`，成功显示后端返回信息，失败显示「后端未连接」，不会崩溃。
- 故障模拟页、历史记录页为布局占位，明确标注功能尚未实现。
- `.env.example` 提供前端 API 地址配置。

### 3.3 已实现接口

| GET | `/api/health` | 健康检查，返回服务状态、项目名称与版本 |

## 4. 本地启动

### 4.1 后端

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

- 健康检查：<http://127.0.0.1:8000/api/health>
- 接口文档：<http://127.0.0.1:8000/docs>

### 4.2 前端

```bash
cd frontend
npm install
npm run dev
```

- 开发地址：<http://127.0.0.1:5173>（以终端输出为准）

### 4.3 测试与构建

```bash
# 后端测试
cd backend && pytest

# 前端生产构建
cd frontend && npm run build
```

## 6. 开发约定

1. 使用 `main` 分支作为主干，功能开发建议使用独立分支后合并。
2. 遵循 `.gitignore` 约定：不提交 `.env`、密钥、数据库文件、虚拟环境、`node_modules`、构建产物。
3. 新增环境变量时同步更新对应的 `.env.example`（仅示例值）。
4. 文档中的功能状态须与实际实现保持一致，不得将规划内容描述为已完成。
